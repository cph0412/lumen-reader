# Lumen Reader 产品分析：竞品拆解、能力盘点与 90 天路线图

> 调研时间：2026 年 10 月。方法：竞品官网、定价页、帮助文档与公开评测（链接见文末），结合 `docs/CONTRACT.md` 与当前仓库实现。价格均为公开标价，可能随地区与促销变化。
>
> 结论先行：Lumen 的机会不是再做一个翻译器，而是把"读完并记住"做进一个本地应用——本地书库 + 全局取词 + AI 语境 + SRS，四件事目前无人做全。

## 1. 一句话定位与目标用户

**Lumen 是给中文读者的桌面英文精读工作台：书在本地，词在句子里查，AI 讲语境，复习自动排。**

三个"不做"：不做内容平台，不做通用翻译器，90 天内不做社交。它只回答一个问题：**用户打开一本英文书，能不能读完，读完能不能记住。**

### 1.1 用户分层

| 人群 | 真实任务 | 现在的替代方案 | 愿意为什么付费 |
| --- | --- | --- | --- |
| 备考（考研/雅思/托福/GRE） | 真题、外刊、学术词汇；今天记的词下次考试要能用 | 欧路词典 + Anki + PDF 打印 | 词表标记、复习闭环、Anki 导出；买断优先 |
| 大学生 | 教材、论文、原版书；预算敏感，设备是笔记本 | 沉浸式翻译免费版 + 欧路免费版 | 便宜的 AI 额度、PDF/EPUB 导入 |
| 职场英语 | 邮件、文档、网页、截图；要快、要准、不打断 | Bob、沉浸式翻译、浏览器插件 | 取词速度、隐私、"不要上传我的文件" |
| 原版书爱好者 | 长篇阅读、排版舒服、双语对照、能听 | Kindle（中国区已停）、微信读书 | 排版与书库、TTS、跨设备、不折腾 |

四类人有一个共同点：**他们不是不会查词，而是查完就忘、查着查着就不读了。** 这是 Lumen 所有功能判断的起点。

### 1.2 核心场景与各自的胜负手

- **精读**：每个词都认识，连起来不懂。胜负手是句子结构、语境义、文化背景，不是词典释义。
- **泛读**：连续读 30 分钟不被打断。胜负手是"忍住不查"——行内提示、已会词遮蔽、难度匹配。
- **查词**：任何应用里看到英文，0.5 秒出结果。胜负手是全局入口与 OCR，不是词库大小。
- **复习**：通勤、睡前的 5–15 分钟。胜负手是队列质量与单卡节奏，不是卡片数量。
- **通勤**：只有手机和耳朵。胜负手是 TTS 与逐句复读，这是 Lumen 目前完全缺失的场景。

## 2. 竞品拆解

### 2.1 九个玩家，一句话判断

- **Readlang**——最接近"阅读 + 查词 + 复习"的原型，AI 语境与 Anki 导出都有，免费版每天限 10 次短语与语境解释；但它以网页和移动端为主，没有桌面全局取词与本地书库。[readlang.com](https://readlang.com/)
- **LingQ**——内容平台型选手，用"已知词/生词"高亮把阅读变成可量化的学习；核心资产是它的内容与社区，不是你的书，价格带也偏高。[lingq.com](https://www.lingq.com/en/pricing/)
- **eJOY English**——视频优先的"全能学习包"，双字幕、PDF、手机扫描取词、AI 语法、SRS 游戏俱全，性价比很凶；但阅读器不是主战场。[ejoy-english.com](https://ejoy-english.com/en/pro-dict)
- **沉浸式翻译**——双语翻译基础设施，网页、PDF、EPUB、字幕、图片、漫画全覆盖，可接自己的模型；只解决"看懂"，没有生词本与 SRS，也非开源。[会员协议](https://immersivetranslate.com/zh-Hans/docs/MEMBERSHIP-TERMS/)
- **Language Reactor**——视频学习的最佳单点，双字幕、点词、PhrasePump、Anki 导出；但只有 Chrome 扩展，没有书阅读器与 EPUB 导入。[功能档案](https://comprehensibleinput.io/apps/language-reactor)
- **Kindle Word Wise**——行内提示的黄金标准，困难词上方显示简短释义，配合 Vocabulary Builder 收集生词；但只有单词级提示、没有 AI 语境。**Kindle 中国区已于 2024 年 6 月 30 日停止云端下载**，"本地书 + 查词"的需求正在寻找新工具。[Word Wise 说明](https://www.justkindlebooks.com/article_jkb/how-to-use-word-wise-and-vocabulary-builder-on-kindle/)、[停服报道](https://m.gmw.cn/2024-06/30/content_1303777632.htm)
- **欧路词典**——中文用户的词典基本盘，屏幕取词、PDF 对照、生词本同步、离线词库；强在查得准、词库厚，弱在阅读排版与 AI 语境。[eudic.net](https://www.eudic.net/v4/en/app/eudic)
- **Bob**——macOS 划词/OCR 的体验标杆，30+ 服务、插件、离线 OCR 与 TTS；但没有阅读器与复习，只服务 macOS。[GitHub](https://github.com/ripperhe/Bob)
- **Anki**——间隔重复的事实标准，FSRS 自 23.10 起内置、AnkiWeb 同步、能扛十万级卡片；但不读书、不查词、没有语境，只是"记忆的执行器"。[Anki](https://apps.ankiweb.net/)、[FSRS 文档](https://docs.ankiweb.net/faqs/what-spaced-repetition-algorithm.html)

### 2.3 三条判断

1. **翻译器和阅读器在分道扬镳。** 翻译器赢在"任何界面都能翻"，沉浸式、Bob、欧路只能铺全平台；阅读器赢在"读得下去"，Kindle、Readlang、LingQ 必须做排版、进度、内容。Lumen 的资源只够赢后者，别用"我们也支持网页翻译"和沉浸式打消耗战。
2. **SRS 是标配，不是卖点。** Readlang、LingQ、eJOY、Anki 都有。真正的差异只有两点：卡片的**上下文质量**（这个词是从哪本书哪句话来的）和**生成成本**（能不能不手动制卡）。Lumen 的上下文卡方向是对的，但还缺"自动生成 cloze"这一步。
3. **价格带是分裂的。** $3–6/月是工具型甜点（Readlang、Language Reactor、eJOY），¥69/月是"AI 额度"定价（沉浸式）。Lumen 应该走 **BYOK + 低价买断**：用户自带 key，边际成本近零，既能压价，又能把"文本只经过你选的模型"讲成隐私卖点。

## 3. 未被满足的需求与市场空位

### 3.1 组合空位：四件套没人做全

把"本地优先 + 全局划词 + AI 语境 + SRS"拆开看，每一件都有人做；合起来看，每家都缺一角：

- Readlang 有 AI 语境和 SRS，但云端、浏览器、无全局取词；
- LingQ 有阅读和复习，但内容是它的、价格高、AI 语境弱；
- Bob/欧路有全局取词和 OCR，但没有阅读器与复习闭环；
- 沉浸式翻译有双语对照，但没有生词复习；
- Anki 有最好的 SRS，但不读书、不查词。

**这不是"功能拼盘"的机会，而是"工作流"的机会。** 用户要的是：读书时划一个词 → 知道这句话里它是什么意思 → 一键收进上下文卡 → 明天复习时看到的还是那句话。这条链路今天要在 3–4 个软件间手动搬运，Lumen 有机会把它压进一个应用。

### 3.2 中文用户读公版英文原著的"i+1"空位

Kindle 中国区停服后，很多人手里有本地英文书（Gutenberg、Standard Ebooks、自购 EPUB），却没有工具告诉他们：**这本书我现在读得动吗？**

Gutenberg 有 7 万多本公版书却没有难度标注；Readlang 的分级内容面向西方语言学习者；LingQ 的内容库不是为中文读者选的；Kindle 已退出中国。用户只能"打开—看不懂—放弃"。

这里有一个具体机会：**用 CEFR + 生词覆盖率 + 已会词，给每本书算一个"你认识 96.4%，平均每页 8 个生词"的数字。** 经验阈值约 95%：低于 90% 频繁卡顿，高于 98% 学不到新词。把选书从"看封面"变成"看数字"，中文市场还没人做。

### 3.3 版权与隐私空位

云阅读器要上传全文，AI 翻译要把选中文本发给第三方，这对读内部文档、未出版译稿的职场用户是硬门槛。反过来，**公版书 + 本地书库 + 自带 key** 合法、可解释、可宣传——这不是技术洁癖，是能写进首屏的差异化。

## 4. Lumen 已实现能力清单

以下以 `docs/CONTRACT.md` 契约 v1 与当前仓库为准；契约之外的能力一律视为未实现。

| 能力域 | 已具备 | 证据/边界 |
| --- | --- | --- |
| 书库 | TXT 导入、编码检测（UTF-8/UTF-16/GB18030）、章节解析、CSS 布面书封、收藏、阅读状态、进度、搜索、书签 | 导入时复制到 `dataDir/books/<id>.txt`，原文件不动；仅 TXT |
| 示例公版书 | 6 本 Gutenberg 公版书：Alice（B1）、Time Machine（B2）、Frankenstein（C1）、Sherlock（B1）、Yellow Wallpaper（B2）、Gift of the Magi（B1） | `resources/samples/samples.json` 已带 level 字段与中文简介；`SOURCES.md` 保留出处 |
| 阅读器 | 章节阅读、目录、上一章/下一章、三种主题（paper/sepia/dark）、字号/行距/字宽/字体/字距、两端对齐、进度保存 | 排版是最强的差异化资产 |
| 划词即译 | 选中文本 → 词/短语/句/段分类 → 免费翻译（Google 非官方端点，失败回退 MyMemory）→ 词典释义 → 缓存（内存 + `cache.json` 600 条） | 网络失败返回带 error 的结果而不抛异常，UI 可降级 |
| AI 语境 | OpenAI 兼容 `/chat/completions`（默认 DeepSeek），返回 translation/sense/grammar/nuance/collocations/examples/alternatives/level 八字段，JSON 归一化、缓存 200 条 | 无 key 抛 `NO_AI_KEY`，友好提示；只到"单次选中"，不到整章 |
| 生词本 | 词、音标、释义、上下文、上下文翻译、来源（书/章）、标签、笔记、mastery 0–5、SRS 字段、去重、CSV 导出 | 卡片自带语境，相对 Anki 的天然优势 |
| SRS 复习 | again 10 分钟 / hard 1 天 / good 2.5× / easy 4×，ease 初始 2.5 并按评分 ±0.15，到期队列 | 经典 SM-2 变体，尚未升级 FSRS |
| 统计 | 今日/累计阅读分钟、词数、查询数、复习数、连续天数、周趋势、热力图 | 由 saveProgress 与 lookup/review 记录，按本地日期聚合 |
| 全局划词浮窗 | Windows 全局热键 → `SelectionGrabber.exe` 模拟 Ctrl+C 取词（并恢复剪贴板）→ 420×560 透明浮窗 `quick.html` | 覆盖任何应用，但依赖"可复制"；截图/OCR 未实现 |
| 设置与数据 | AI baseUrl/model/temperature、翻译 provider、阅读器参数、热键、safeStorage 加密 API key、JSON 原子写、导入导出 | 数据模型简单，万级词条需 SQLite |

**缺口**：只支持 TXT；没有 EPUB/PDF/网页导入与 OCR；AI 只服务"选中的一段"而非"这一章"；没有 cloze、Anki/欧路导出与同步；全局取词在扫描 PDF、图片、视频字幕上会失效。

## 6. 体验优化建议

1. **划词卡按"先答案、后解释、再收藏"三层组织。** 首屏只放单词、音标、一句语境翻译、收藏按钮；"AI 解析/搭配/例句/语法"折叠到第二层。默认不自动调用 AI——省 token、省等待，也避免每次划词都弹一大段分析。卡片出现在选区下方 12px，越界翻转，不遮正在读的那一行。
2. **复习要制造心流，不是报表。** 全屏单卡、隐藏侧栏、顶部只留"今日 12/37"；Space 显示答案，1–4 评分，again 的卡 10 分钟后回炉；中途不弹统计与成就；结束只给一句"今天记住了 8 个词，下次复习明早 9:00"。目标是让用户机械做完，而不是欣赏数据。
3. **空状态是产品说明书。** 首启三步：导入一本书 → 打开示例书 → 选择是否配置 AI。空书库给"一键添加 6 本公版书"，空生词本给"从正在读的书里划一个词"，空统计给"读 10 分钟就会出现在这里"。每个空状态都要有可点击的下一步。
4. **首次配置 AI key 要能跳过。** 默认不要求 key，免费翻译与本地词典先跑起来；设置页给 DeepSeek/OpenAI/自定义三个预设 + "测试连接"；用一句人话说明边界——"只发送选中的片段和前后各一段，不发送整本书"；key 用 safeStorage 加密。没有 key 时按钮写"配置 AI 解析"，不要置灰。
5. **免费额度与失败降级要可预期。** 翻译失败依次尝试：重试 → 换引擎 → 只显示词典 → 显示原文并提示"翻译服务暂不可用"；AI 超时/429 不阻塞阅读，提示"已跳过本次解析"；离线时排队，恢复后提示。用户可以接受失败，不能接受"转圈 30 秒什么都没有"。
6. **全局热键要防冲突、可发现、可恢复。** 注册失败时列出冲突程序并引导换键；浮窗只在非 Lumen 窗口触发；取词失败提示"当前应用不允许复制，试试截图取词（P1-4）"，不要静默失败；剪贴板恢复已实现，但要覆盖图片/富文本，避免"取一次词，剪贴板被清空"。

## 7. 90 天路线图（2 周一个迭代）

| 迭代 | 时间 | 主题 | 交付 | 可验收结果 |
| --- | --- | --- | --- | --- |
| S1 | W1–2 | 导入管线 v2 | EPUB/Markdown/URL 剪藏 + 清洗规则 + 导入预览与失败原因 | 10 本 EPUB 成功 ≥9；章节正确；网页正文可读；失败可操作 |
| S2 | W3–4 | 难度与覆盖率 | 词表引擎 + 词形还原 + 每章覆盖率 + 书库难度徽章 + "已会词"标记 | 覆盖率与人工抽检误差 ≤3%；单章 <300ms；标记后即时重算 |
| S3 | W5–6 | 段落双语 + 整章精读 | 段落懒翻译/缓存 + 精读卡（主旨/难句/文化点/3 问）+ 成本上限 | 3000 词精读 ≤¥0.3；缓存命中 >80%；关 AI 与无 key 不影响阅读 |
| S4 | W7–8 | 记忆闭环 | cloze 自动生成 + 读后提问 + 复习心流改版 + 到期队列 | cloze 可用率 >70%；复习 20 张 ≤4 分钟；回炉生效 |
| S5 | W9–10 | 桌面入口 | 屏幕 OCR 取词 + 浮窗 v2 + 命令面板 + 热键冲突处理 | 印刷体截图准确率 >95%；取词 <1.5s；冲突有引导 |
| S6 | W11–12 | 生态与隐私 | Anki APKG 导出 + FSRS + Ollama 本地模式 + 离线词典 | APKG 可在 Anki 打开复习；FSRS 抽检一致；断网 + Ollama 可划词解析 |
| Buffer | W13 | 性能与稳定 | 10MB 大书、1 万生词、启动 <2s、打包签名 | 无未捕获异常；长章节滚动 60fps；冷启动 ≤2s |

依赖关系：S2 依赖 S1 的章节结构；S3 依赖 S2 的段落切分与缓存；S4 依赖 S3 的上下文卡；S5 与 S6 可并行，但 S6 的 FSRS 会改 S4 的调度逻辑，建议 S4 先把评分接口抽象出来。

## 8. 风险与边界

- **版权**：只处理用户自有或公版文本；不内置版权书；不做公开书库与分享；Gutenberg 来源保留 `SOURCES.md` 与许可说明；导入时声明"请确认你拥有该文本的使用权"。
- **隐私**：选中文本会发给第三方（Google/MyMemory 或用户配置的 AI）。首次启用须在设置页明示，并提供"仅本地词典"模式；日志不记录全文；key 用 safeStorage 加密；遥测默认关闭。
- **AI 幻觉**：AI 释义、例句、语法一律标"AI 解析"、可折叠、可关闭；字段做校验，不确定时用"可能是"；不让 AI 改写原文。
- **性能**：JSON 存储在万级词条时读写放大，P1 迁移 SQLite（或 sql.js）；长章节虚拟滚动；覆盖率用 Set + 预计算，不逐页重算；缓存设上限。
- **跨平台**：Windows 取词助手是 exe + 模拟 Ctrl+C，macOS 需要辅助功能权限与 AX API，Linux 没有统一方案。短期明确"Windows 优先"，别把"跨平台"写进文案；打包、签名、更新是隐性成本。

## 9. 如果只做三件事

1. **把"能不能读"变成数字。** 覆盖率 + 已会词遮蔽 + i+1 推荐。这是用户打开书前的第一个决策，也是 Lumen 能立刻区别于 Readlang/LingQ 的地方——它们说"词什么意思"，Lumen 说"这本书你读得动"。
2. **把"AI 词典"升级成"整章精读"。** 段落按需双语 + 精读卡（主旨、难句、文化点、问题）。单次划词是工具，整章理解才是老师；这是从"查词软件"跨到"阅读教练"的一步。
3. **把"收藏"闭环成"记住"。** cloze 自动生成 + FSRS + Anki 导出。留存不靠功能数量，靠"我昨天收藏的词今天真的记住了"；没有这一步，前面所有体验都只是一次性新鲜感。
